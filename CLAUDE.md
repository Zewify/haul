# Komizo

A free Mac download manager in the mould of Internet Download Manager, by Zewify: a browser extension hands downloads to the app, which fetches them over several connections, resumes them, queues them, and grabs video from pages.
Free and published from zewify.com (owner's decision, 2026-10-14): no Pro tier, no Mac App Store edition, one build with everything in it.
Named Komizo on 2026-10-17 (Greek κομίζω, "I carry, I bring home"), the owner's pick. It was Haul until 0.2.1, renamed because another free Mac download manager called Haul (github.com/sibiraj-s/haul) had launched on 2026-10-01, and Downhaul for 0.3.0 only. The design and plan docs below, and the release notes up to 0.3.0, keep the names of their day. A desk search found no app or project called Komizo (Komiko, a sales tool, is close; the owner accepted that); the owner chose no lawyer's clearance search (free, not promoted). Old `zewify.com/haul/` and `/downhaul/` links and both old install commands redirect to Komizo's, and the installer removes an old Haul.app or Downhaul.app.
Design: `docs/superpowers/specs/2026-10-13-haul-design.md`. Plan: `docs/superpowers/plans/2026-10-13-haul.md`. Launch work: `docs/launch-checklist.md`.

## Layout

- `Core/` — the `KomizoCore` package: the model and library, filenames, the probe, the segment planner, the part file, `DownloadTask`, `DownloadEngine` (the queue), the local `ExtensionServer`, streams (`HLS`, `DASHManifest`, `StreamPlan`, `SegmentDownloader`, `StreamTask`), DASH joining (`DashTask`, `Muxer`), the Facebook page parser. Foundation, Network and AVFoundation only; no AppKit.
- `App/` — the SwiftUI app: `Model/AppModel.swift` (library, engine, server delegate, catches), `UI/` (main window, rows, segment map, catch panel, settings, Pro, menu bar).
- `Extension/` — the WebExtension shared by Chrome (load unpacked) and Safari (packaged by the `KomizoSafari` target): `background.js` (module service worker), `content.js`, popup, options, `lib/` (pure logic, node-tested), `icons/`.
- `SafariExtension/` — the Safari app extension's handler and Info.plist.
- `AppTests/` — app-hosted tests. `scripts/` — build, test, install, icon, screenshots, the Chrome end-to-end.
- `project.yml` — XcodeGen spec. The `.xcodeproj` is generated and gitignored; never edit or commit it.

## Commands

- `./scripts/test.sh` — core package, extension logic (`node --test`), then hosted tests. Silent on success; the exit code is the verdict. Run before every commit.
- `./scripts/build.sh [Debug|Release]` — generates the project and builds; prints the app path.
- `./scripts/install-local.sh` — Release build into `/Applications/Komizo.app`, then launches it.
- `KOMIZO_CHROME=<chrome-for-testing> node scripts/e2e-chrome.mjs <page-url> <file-name>` — the Chrome end-to-end against a running Komizo (see the script's header).
- `KOMIZO_CHROME=<chrome-for-testing> node scripts/e2e-media.mjs <page-url> [seconds]` — the grabber end-to-end: opens a page in a throwaway Chrome, prints what the sniffer found, grabs it, and waits for the file. Needs a running Komizo.
- `swift scripts/make-icon.swift App/Resources/Assets.xcassets/AppIcon.appiconset Extension/icons` — re-renders the icons.
- `swift scripts/window-shot.swift <dir> <prefix>` — screenshots every Komizo window.

## Rules that are not obvious

- **There is no paywall.** `Limits` (32 connections, 8 downloads at a time) are the engine's own ceilings. The Pro tier, licences, `licensetool`, the `FeatureGate` and the store/direct editions were removed on 2026-10-14 when the owner made Komizo free; the server's `features.media` field stays `true` so the extension's check keeps working.
- **The extension talks to the app over `127.0.0.1:48512`**, never native messaging. Every write needs an `Origin` with an extension scheme plus the bearer token issued at pairing; `/status` is open. Pairing is an `NSAlert` the user approves once per browser.
- **The engine claims a download's name at `add`** (`Filename.available` plus an empty part file), so two downloads of one name never share a part file. The task re-probes on every start; a changed validator or size restarts from zero, once.
- **`HTTPStream` has flow control**: at most about 1 MiB waits unread per connection; past that the data task is suspended until the reader acknowledges chunks (`consumed`), so a slow reader slows the socket instead of filling memory.
- **The speed limit is one `SpeedLimiter` for the whole engine** (`DownloadEngine.speedLimit`, from `Settings.effectiveSpeedLimit`; `limitSpeed` and `speedLimit` are kept apart so the menu toggles without losing the number). Readers spend bytes in 64 KB slices *before* writing them (`DownloadTask.write`, `MediaFetcher`); a token bucket with a quarter second of credit and debt makes the waits. Suspending the socket alone did not hold the cap: the kernel buffer kept filling and arrived as one multi-megabyte chunk, a 7 MB/s burst under a 2 MB/s cap (measured 2026-10-17). A cap change releases every wait at once. Engine tests that need downloads in flight hold them with `speedLimit = SpeedLimiter.minimum` rather than a slow test server, which raced on a busy machine.
- **Settings opens through SwiftUI's `openSettings`**, lent to `WindowManager` by the menu bar icon; the `showSettingsWindow:` action does nothing for a SwiftUI Settings scene on current macOS and left the menu's Settings… dead until 2026-10-17.
- **Rebalancing** happens in `DownloadTask.fetchLoop`: when a segment finishes, the largest remaining range over 2 MiB is split and its tail given to the idle connection; a worker stops writing at its (possibly shortened) end.
- **The library is saved every second while anything runs** (`AppModel.start`), and at once on every change, so a crash loses at most a second of segment state.
- **Google Chrome 137+ ignores `--load-extension`**; the end-to-end uses Chrome for Testing. Users load the extension unpacked, for good: the owner chose no Chrome Web Store (2026-10-17). The release zip holds `Komizo.app` and `Extension/` side by side (`scripts/package.sh`, tests left out), and `scripts/install.sh` puts the extension in `~/Library/Application Support/Komizo/Extension`, swapped in place like the app, so Chrome's unpacked entry keeps its path across updates and only needs a reload. It is never put inside the app bundle, which is signed. Settings → Browser shows the path and copies it (`Format.extensionFolder`).
- **Chrome lists an idle extension worker nowhere**; the e2e finds Komizo's id through `chrome://extensions` and talks to the background through the popup page.
- **Safari needs the extension turned on** in Safari → Settings → Extensions; an ad-hoc build needs "Allow unsigned extensions" in the Develop menu, each Safari launch.
- **The grabber sees two kinds of thing.** The sniffer (`webRequest`) records media responses: HLS playlists (`hls`), DASH manifests (`mpd`) and plain media files (`file`), with chunk parameters (`bytestart`, `byteend`, `range`) stripped so a file fetched in pieces is one item; the page scan (`KomizoMedia.findInPage`, asked through the content script) pulls muxed progressive URLs out of the page's own scripts (Facebook's `browser_native_hd_url`/`sd_url`) and plain `<video>` sources.
- **The popup lists the stream, not its pieces** (`KomizoMedia.tidyMedia`): once a tab has a playlist or manifest, plain files from that stream's host are its segments and are hidden; a master playlist is read once (`hlsChildren`) so its variant and audio playlists are hidden; ad-network hosts (`AD_HOSTS`) are never listed. The per-tab list keeps 30 items and evicts plain files first (`recordMedia`), because a player fetches hundreds of segments and they once pushed the `.mpd` itself out.
- **Streams, HLS or DASH, resolve to a `StreamPlan`** (`StreamSource.plan`): a video track and, when the site keeps sound apart, an audio track. HLS takes the highest-bandwidth variant and its group's default `EXT-X-MEDIA TYPE=AUDIO` rendition (TED does this; before 2026-10-17 Komizo saved such streams silent); `EXT-X-BYTERANGE` segments are fetched as ranges. `DASHManifest` reads any site's MPD: `SegmentTemplate` (`$Number$`/`$Time$`, `SegmentTimeline`), `SegmentList` and `SegmentBase`, the longest period, H.264 over HEVC over AV1, VP9 and WebM skipped. `StreamTask` saves one track straight into the download's part file, or two into `<name> (video).komizopart` and `(audio).komizopart` one after the other (`mediaTrack` says which, for resume) and joins them with `Muxer`.
- **The popup knows which item is the video being watched** (2026-10-17). The content script reports the visible, started `<video>` elements, shadow DOM included (Reddit's player lives in one), ranked by their own picture size rather than their box (X stretches 244×224 GIF clips over bigger boxes than the tweet's video), with `loop` ones last. The app's `POST /inspect` (`MediaInspector`) reads each sniffed item's length and tracks: a file's first 256 KB for its `moov` (`MP4Probe`: `mvhd`, `trak`/`hdlr`/`tkhd`, `mehd`, `sidx` for fragmented files), refetching up to 16 MB when a long video's `moov` is cut short (a track past the cut must not read as missing), and a playlist's segment lengths; it reports live streams and links it cannot open (Dailymotion's one-time `cdndirector` playlist; its `dmxleo` ".m3u8" is an ad schedule). The extension then marks the playing item by source or, for a `blob:` player, by length (`KomizoMedia.markPlaying`): TikTok's largest file was a feed neighbour, Reddit's first stream an ad. A video-only file and an audio-only file of one length become a joined "Video + sound" item (`pairTracks`), which is how Instagram and Bilibili come out with sound; Bilibili's tracks are `.m4s` files fetched in byte ranges, which the sniffer counts as files when Content-Range gives a total of 1 MB or more. Error responses are never recorded.
- **The tested-sites list** is printed twice: the app's toolbar "?" popover (`App/Sources/Model/TestedSites.swift`, `UI/TestedSitesView.swift`) and zewify.com/komizo (the zewify repo's `src/komizo/data.ts`, `testedSites`/`unsupportedSites`). Change both together, and only list a site after a grab of it was checked by its file's tracks and a frame.
- **Names come from the page** (`Filename.displayTitle`): the tab title, or `og:title` when the tab title is only the site's name; first line only, " : " and "/" made dashes (a Reddit title once became "CompetitivePUBG.mp4"), and cut to 150 bytes, because a two-track download's parts add " (video).mp4.komizopart" and a caption once pushed them past 255 bytes, which macOS reports as a permission error.
- **Streams are read when the catch arrives** (`AppModel.makeCatch`), so a protected (`ContentProtection`, `SAMPLE-AES`), live (`type="dynamic"`, or an HLS media playlist with no `EXT-X-ENDLIST` and not `PLAYLIST-TYPE:VOD`; Rumble's 24/7 channels) or unplayable stream is refused at once, in a plain sentence the popup shows, and a DASH manifest whose tracks are each one whole file becomes a `dash` download through the segmented file engine. Vimeo encrypts its streams (CENC, Widevine and PlayReady; checked 2026-10-17), so Vimeo is refused as DRM; saving DRM video is out of scope for good.
- **Checked end to end on 2026-10-17** with `scripts/e2e-media.mjs`, which judges a grab by the new download in Komizo's own library (state, file, `mediaNote`) and presses Start in the catch panel through the AX API (`scripts/press-start.swift`, used by `catch-panel.mjs`), never a Return keystroke, which goes to whatever app is in front. System Events cannot read SwiftUI's button labels (they live in `AXDescription`; its `name` and `description` come back empty or "button"), so it is the wrong tool for checking them; the buttons are labelled. See the round in `docs/launch-checklist.md`.
- **DASH sites are joined natively.** `Extension/lib/media.js` `findDashSets` reads the DASH representations Facebook embeds in every page (`all_video_dash_prefetch_representations`, whole-file URLs, the video id inside each URL's `efg` parameter) and offers one "video + audio" item per codec family, H.264 first, the page's own video first; `DashTask` downloads the two tracks as ordinary segmented downloads and `Muxer` joins them with an AVFoundation passthrough export (no re-encoding, no ffmpeg). VP9 is left out because AVFoundation cannot read it; AV1 is offered with a "newer Macs only" note. A finished grab is inspected (`MediaInfo`) and a silent file gets `mediaNote`, shown in its row.
- **Facebook serves different video to different browsers.** As Chrome it embeds a DASH table (`all_video_dash_prefetch_representations`), often VP9- or AV1-only, and VP9 in MP4 is what AVFoundation and QuickTime cannot read, so a sniffed track "does not play". As Safari it embeds progressive H.264 720p "HD" and SD files (`browser_native_hd_url`/`sd_url`), listed per video right after that video's `dash_manifest_url?v=<id>`, which is how `FacebookPage.nativePairs` tells them apart. A plain fetch with a browser user agent gets HTTP 400 and the crawler endpoints serve placeholders, so `PageReader` (an offscreen `WKWebView`, Safari agent first, then Chrome) is the only way the app reads a page by itself. A reel's URL id is the video's own id in these tables; a `/share/` link names none, so only then does the page's first video count.
- **The extension's surest Facebook grab is the page itself**: `pageReaderItem` offers "This video · 720p H.264 · Komizo reads the page" (`kind: page`); the app loads the page as Safari and takes the H.264 file, lending the SD file's sound if the HD one is silent (`DashTask` keeps a first part that already has sound). Pasted Facebook links in Add URL take the same path.
- **The menu bar icon is the app icon** (`MenuBarGlyph` in `KomizoApp.swift`), the way TickThock's is: `NSApp.applicationIconImage` cropped to its tile and drawn at 18 points, never a template, so changing the icon changes it too; while anything downloads, a thin blue bar along the tile's bottom edge shows the combined progress.
- **Media is named after the page title** (`Filename.mediaName`), because CDN names are hashes; a `Content-Disposition` name still wins.
- **Debug launch arguments:** `-KomizoShow settings|catch`.
- **A Debug build shares the installed app's sandbox container**, `~/Library/Containers/com.zewify.komizo`, and so its `library.json`.
- zsh has a `log` builtin; use `/usr/bin/log stream --predicate 'subsystem == "com.zewify.komizo"'`.
- Zewify rule: nothing in the app, repo or site may identify the person who builds it (the Developer ID signature on the direct edition is the accepted exception).

# Haul 1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A testable Haul: a Mac app that downloads files over several connections with pause and resume, queues them, and receives downloads from a Chrome or Safari extension, with the direct edition also grabbing media and HLS streams.

**Architecture:** `HaulCore` (Swift package) holds the engine, model, server and gate with no AppKit; `App/` is a SwiftUI app with a main window, catch panel, Settings and menu bar item; `Extension/` is one Manifest V3 WebExtension packaged for Safari by an app extension target and loaded unpacked in Chrome.
The edition is the `DIRECT_EDITION` compilation condition.

**Tech Stack:** Swift 6, SwiftUI, AppKit, Network.framework, CryptoKit, XcodeGen, Xcode 26; JavaScript (MV3) with `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-13-haul-design.md`

## Global Constraints

- macOS 15 deployment target, Swift 6 language mode, strict concurrency.
- Bundle ID `com.zewify.haul`; Safari extension `com.zewify.haul.safari`; tests `com.zewify.haul.tests`.
- App Sandbox on, with `com.apple.security.files.downloads.read-write`, `com.apple.security.files.user-selected.read-write`, `com.apple.security.files.bookmarks.app-scope`, `com.apple.security.network.client`, `com.apple.security.network.server`.
- Server listens on `127.0.0.1` only; default port 48512.
- Free: 4 connections, 2 concurrent. Pro: 32 connections, 8 concurrent. Segment floor 512 KiB; split threshold 1 MiB; rebalance threshold 2 MiB; retries 5 with 1, 2, 4, 8, 16 s.
- Licence prefix `HAUL1-`, product `haul-pro`.
- Nothing in the repo may match `~/.config/zewify/identity-denylist`.
- Signing: committed `App/Signing.xcconfig` ad hoc, local override in gitignored `App/Signing.local.xcconfig`.
- Markdown: one sentence per line.

## Review Focus

1. A URL that redirects to a server without range support must still download as a single stream, not fail (Task 4 test `probeFollowsRedirectAndFallsBack`).
2. A `Content-Disposition` filename containing path separators or leading dots must be sanitised, never written outside the folder (Task 3 test `filenameIsSanitised`).
3. Two downloads of the same filename at the same time must not share one part file (Task 6 test `concurrentSameNameGetsDistinctPartFiles`).
4. A `/downloads` POST with a non-http(s) URL (`file://`, `javascript:`) must be rejected with 400 (Task 8 test `rejectsNonHTTPURL`).
5. Resuming after the app was killed mid-download, with the part file shorter than the saved segment counts, must re-fetch rather than trust the counts (Task 5 test `resumeTrustsPartFileOverCounts`).

### Task 4: Test server and probe

**Files:** `Tests/TestServer.swift`, `Engine/Probe.swift`, `Tests/ProbeTests.swift`.

**Test server:** an `NWListener` on an ephemeral `127.0.0.1` port serving a `Data` blob at any path.
Options (vars on the server): `supportsRanges`, `hidesLength`, `etag`, `dropAfterBytes: Int?` (closes the connection after that many body bytes, once per connection count, then resets), `redirectPath: String?` (302 from `/redirect` to the blob), `contentDisposition: String?`, `delay`.
Records every request (`method, path, headers`) for assertions.
Must handle `Range: bytes=a-b` with `206`, `Content-Range`, and `416` for a bad range; `HEAD`.

**Produces:**
```swift
public struct ProbeResult: Sendable { finalURL: URL, size: Int64?, acceptsRanges: Bool, validator: String?, suggestedName: String, contentType: String? }
public enum Probe { static func run(_ url: URL, context: RequestContext, session: URLSession) async throws -> ProbeResult }
```
Probe sends `GET` with `Range: bytes=0-0` and the context headers; `206` + `Content-Range: bytes 0-0/N` → size N, ranges true; `200` → size from `Content-Length` (nil if absent), ranges false; the body is cancelled after headers (use `bytes(for:)` and break after first chunk, or a delegate that cancels in `didReceive response`).

- [ ] Tests: ranges server → size and `acceptsRanges`; no-ranges → false; hidden length → nil; `probeFollowsRedirectAndFallsBack` (Review Focus 1); name from disposition beats URL; context headers (`Cookie`, `Referer`, `User-Agent`) appear in the recorded request.
- [ ] Commit.

### Task 5: Planner, part file, download task

**Files:** `Engine/SegmentPlanner.swift`, `Engine/PartFile.swift`, `Engine/DownloadTask.swift`, `Tests/PlannerTests.swift`, `PartFileTests.swift`, `DownloadTaskTests.swift`.

**Produces:**
```swift
public enum SegmentPlanner {
    static func plan(size: Int64, connections: Int) -> [Segment]            // n = min(connections, size/512KiB, ≥1); equal split, last takes remainder; size<1MiB → 1 segment
    static func rebalance(_ segments: [Segment]) -> (donor: Int, newSegment: Segment)?  // largest remaining > 2 MiB → split its unwritten half; returns nil otherwise
}
public final class PartFile: Sendable {   // owns the URL; preallocate(size:); writer(at offset:) -> FileHandle; actual length; finish(as name:) -> URL (numbered on collision); remove()
}
public struct Progress: Sendable { bytes: Int64, total: Int64?, segments: [Segment], bytesPerSecond: Double, eta: TimeInterval? }
public actor DownloadTask {
    init(download: Download, gate: FeatureGate, session config, folder: URL, onProgress: @Sendable (Progress) -> Void)
    func start() async throws -> Download          // runs to completion (finished) or throws; updates download.segments/state; returns the final record
    func pause() async -> Download                 // cancels tasks, returns record with segments
    func cancel() async
}
```
Internal: a `SegmentWorker` per segment using `URLSession` delegate streaming (`URLSessionDataDelegate` in a class with a continuation; chunks written at `start+written` via the segment's handle); `written` updated under the actor; a progress timer at 100 ms computes speed over a 3 s window; retry with the backoff table; validator check (`If-Range`-free: compare `ETag`/`Last-Modified` of each 206 with the probe's; mismatch → `.changed` error → restart from zero once).
Resume: `start()` on a download whose `segments` are non-empty skips probe (unless `validator` nil) and verifies `PartFile` length ≥ max(end+1) and clamps each `written` to what the file could hold; if the part file is missing, segments reset.

- [ ] Planner tests: 10 MiB with 4 → 4 equal segments covering exactly 0…size-1 with no overlap; 700 KiB → 1; 3 MiB with 32 → 6 (512 KiB floor); rebalance picks the largest remaining; nil when all under 2 MiB.
- [ ] PartFile tests: preallocates length; writes at offsets land; `finish` renames, numbered collision.
- [ ] DownloadTask tests (against TestServer with a 6 MiB random blob): byte-identical result with 4 connections; single stream when ranges unsupported with `resumable == false`; pause after ≥ 1 MiB then resume completes and the server saw `Range` requests starting past 0; `dropAfterBytes` recovers (request count > segments); `resumeTrustsPartFileOverCounts` (Review Focus 5: truncate the part file, resume, verify bytes); changed etag restarts and still verifies; rebalance happens (with 2 connections and a slow first half the recorded ranges include a split).
- [ ] Commit after each green group.

### Task 7: HTTP parsing and the extension server

**Files:** `Server/HTTP.swift`, `Server/ExtensionServer.swift`, `Tests/HTTPTests.swift`, `Tests/ExtensionServerTests.swift`.

**Produces:**
```swift
public struct HTTPRequest { method, path, headers: [String: String] (lowercased keys), body: Data; static func parse(_ buffer: inout Data) -> HTTPRequest? (nil until complete) }
public struct HTTPResponse { status: Int, json: Encodable? / body; func serialised() -> Data }   // adds Content-Type, Content-Length, Connection: close

public protocol ExtensionServerDelegate: AnyObject, Sendable {
```

Rules: `Origin` must match `^(chrome-extension|safari-web-extension|moz-extension)://` for every POST; `/downloads` and `/media` need `Authorization: Bearer <token>`; `/media` is 404 unless `status.features.media`; `/status` has no checks; unknown → 404; bad JSON → 400; the URL must parse with scheme http or https (`rejectsNonHTTPURL`, Review Focus 4).
Replies carry `Access-Control-Allow-Origin: <origin>` and answer `OPTIONS` with the allow headers so a fetch from any browser passes preflight.

- [ ] Tests use `URLSession` against the server on an ephemeral port: status; pair approved returns token; pair denied 403; downloads without token 401; wrong origin 403; good request 201 with the delegate's id; media 404 in store status, 201 in direct; `rejectsNonHTTPURL`.
